# AGENTS.md — how to maintain this wiki

This folder is a wiki that you, the agent, write and maintain for the user through the Stet MCP server. Stet has no model: it stores, validates, checks and displays. You write and judge.

## Layers

- `inbox/` — raw files the user dropped. Read them with `queue_next`.
- `sources/` — immutable. `sources/imports/` holds processed inbox files, `sources/sessions/` holds session notes you wrote.
- `fiches/` — the wiki: one markdown file per fiche, linked with `[[Title]]`.
- `index.md` and `log.md` — generated by Stet. Never edit them by hand.

Always write through the Stet tools, never with your file tools: Stet checks the format, moves files and keeps the index and the log in sync.

## A fiche

- One idea, decision, concept, person or project per fiche. Title = what it is about, in a few words.
- Body in markdown: what is true, why, and since when. Short paragraphs. Link related fiches with `[[Title]]`.
- At least one source and one tag. Sources are paths under `sources/` or `inbox/`, or URLs (`https://...`, a commit or ticket URL). Never cite a fiche as a source: link it in the body.
- You always write drafts. Only the user validates. Updating a validated fiche sends it back to draft.
- If a write is refused, read the problems, fix them and retry. Do not ask the user about format errors.

## Operations

### Capture during a session (most valuable)

While working on anything else, when something durable happens — a decision and its reason, a problem solved, a fact learned, a convention agreed — propose once: "Want me to keep this in Stet?" At most one unsolicited proposal per session. If the user says "keep this", do it without further questions:

1. `write_session_note`: a short account of what was established and how, with artefacts (file paths with commit, URLs, tickets) when they exist.
2. `search` for an existing fiche on the topic. Update it (`update: true`) rather than creating a near duplicate.
3. `write_fiche`, citing the session note and the artefacts.

If `status` says capture is disabled for the current folder, never propose or write anything.

### Ingest the inbox

1. `queue_next` gives the oldest waiting item.
2. Write or update the fiches it supports, citing it as `inbox/<name>` (Stet moves it to `sources/imports/` and rewrites the path).
3. `complete_item` with the titles of the fiches it produced, or an empty list if it held nothing worth keeping.

### Answer from the wiki

Before answering a question the wiki may cover, `search`, then `read` the relevant fiches and cite them by title. Use `index` (paginated) to browse. Never load the whole wiki at once.

### Check

- `lint` lists mechanical problems: broken links, orphans, missing sources, duplicates, stale items. Fix what you can through `write_fiche`.
- Deep check, when the user asks: read fiches sharing tags and look for contradictions and outdated facts. Fix them in a draft update and say what changed in the body. Record the pass with `log`.
